## 方案与取舍

采用原生小程序 WXML / WXSS / JS，无前端框架和运行时第三方依赖。项目从零开始，页面数量有限，原生方案可直接在已安装的微信开发者工具中编译；相比跨端框架，减少了额外构建和平台适配。

业务逻辑与数据适配分开。`shared/domain.js` 负责北京时间和统计，`shared/service.js` 定义业务与权限，`shared/memory-store.js` 提供事务隔离的本机存储。构建脚本把三者原样同步到小程序与云函数，不维护两套不同口径的逻辑。

本机使用同一业务服务和 `wx.setStorageSync`，图片使用微信本地文件保存。组队、分享、监督在本机模式拒绝创建并说明云端依赖。真实云端使用 `wx.cloud.callFunction`、云数据库、私有云存储与微信内容安全接口，不在客户端保存 AppSecret。

## 页面和主流程

四个主标签：今日、小队、战绩、我的。附属页面：开启目标、打卡表单与成功态、分享卡/小队邀请、隐私说明。

创建目标 → 今日目标 → 可选照片和感想 → 确认完成 → 今日状态与战绩同步。一个用户同时只有一个进行中目标；结束目标保留记录。

云端流程：创建小队 → 分享邀请码 → 好友主动加入；生成进度卡 → 接收人只读；生成督促卡 → 接收人主动接受 → 站内每日提醒。邀请不是自动向他人发送消息。

## 数据与一致性

集合和索引见 `cloud/schema.json`，共 9 个集合、6 个业务复合索引，已在该环境创建并回读。集合创建时均选择“所有用户不可读写”，只由云函数访问；实测小程序直接查询 `mm_users` 返回拒绝代码 `-502003`。存储权限已回读为“仅创建者可读写”。

| 对象 | 关键字段与不变量 |
| --- | --- |
| user | 由微信运行时 `APPID + OPENID` 哈希为身份 ID，保存昵称、当前目标 ID、当前小队 ID |
| goal | 分类、自定义内容、周期、开始日期、状态、结束时间。创建/结束与 user 更新在同一事务内 |
| record | 主键为 `goalId + 北京日期`，同一天更新同一记录，保留首次创建时间 |
| team | 随机邀请码作 ID，保存成员数组。每人一队、最多 20 人，由事务校验 |
| share | 随机 192 位令牌、目标、类型、图片开关、7 天有效期和撤销状态 |
| watch | 目标与监督人绑定，可由任一方解除 |
| nudge | 按关系、发送人、接收人和北京时间确定每日主键，避免同一路径重复提醒 |
| limit / upload | 邀请码尝试次数与已通过图片检查的凭证 |

日期由服务端北京时间决定，不接受客户端指定历史日期。当前完成率按已开始天数计算；提前结束后统计截止结束日。周期进度为完成天数 / 完整目标天数。

## 接口与权限

云函数只有 `checkin`，请求 `{ action, data }`，响应 `{ ok, data }` 或 `{ ok:false, error:{code,message} }`。行为及参数以 `shared/service.js` 为准。

身份只从 `cloud.getWXContext()` 获取，忽略请求中的身份字段。每次读取/修改目标检查所有者；队伍只向成员展示昵称、目标与统计，不返回感想和照片。分享只返回对应目标的统计，默认不返回图片。开启图片分享后，由服务端签发 10 分钟临时 URL。感想始终不随分享卡展示。

`share.revoke` 停止通过该链接继续访问，但不会收回已下载内容，也不会解除已经接受的监督关系；关系需在“我的”另行解除。照片文件 ID 路径须属于当前用户，云端适配还会下载校验格式、大小并调用内容安全检查。

输入校验、网络失败、内容检查失败和保存失败均不展示成功。客户端保留打卡表单，已经上传的图片 ID 在当前页重试时复用。同一天重复提交及邀请码重复加入具有幂等性。

## 云端启用、停止和回退

1. 用户已授权云端接入，当前使用既有微信体验版环境。本次没有购买套餐、开启自动续费或接受付费日志服务条款。
2. 在该环境创建 `cloud/schema.json` 中的集合和索引，为每个集合配置 `cloud/database.rules.json`，为存储配置 `cloud/storage.rules.json`。使用者规则参考 [CloudBase 存储安全规则](https://docs.cloudbase.net/storage/security-rules)；云函数事务参考 [事务操作](https://docs.cloudbase.net/database/transaction)。
3. 处理上述依赖审计，配置微信内容安全接口权限；按该 AppID 的实际能力验证文本和图片检查。
4. 部署 `cloudfunctions/checkin`（云端安装锁定依赖）。当前实际运行环境为 Node.js 16.13，内存 256 MB；超时已在原生控制台设置为 30 秒，并用内置 CLI 回读为 Active / 30 秒。`config.json` 中声明超时并不会自动同步该设置，部署后需要核验。首次部署也须核对云调用权限，实际验证文本及图片安全检查；本次已通过这两项真实调用。在 `miniprogram/config.local.js` 填入环境 ID 后重新编译。
5. 用两个不同微信身份验收创建/加入小队、邀请接收、图片归属、只读分享、主动接受监督、每日提醒和解除关系。真实手机验证图片持久化、相册权限、朋友圈分享与跨日行为。
6. 配置、依赖、内容检查或权限验证未通过时停止上传上线；修复并重复对应验证。回退时恢复上一份云函数包与配置；需保留数据库和存储，避免删除用户数据。回退后验证原目标、原记录和分享访问符合预期。

本机体验与云端数据各自独立，切换配置不会自动迁移历史数据。上线需要另行完成账号能力、隐私指引、平台提审与真人验收。
